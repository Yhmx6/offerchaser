# OfferChaser 新手上手全流程

> 面向第一次使用 OfferChaser 的人。按顺序做完即可完成第一轮投递。
>
> 适用版本：2.0.1（5 空间管理台、三套配色）。
>
> 推荐直接使用桌面可运行版；不需要安装 Java、Node.js，也不需要命令行构建。

---

## 0. 先理解这个工具在做什么

OfferChaser 是一款**本机运行**的 BOSS 直聘投递助手，流程是：

```text
搜索采集岗位
  → 本地规则筛选
  → AI 匹配并生成招呼语
  → 联系人/回复检查
  → 每日预算检查
  → 会话身份核对
  → 文字发送确认
  → 图片简历发送确认
  → 写入投递台账
```

它有几个边界必须先知道：

- **只支持 BOSS 直聘**，单用户、单账号、本机使用；
- **不会自动回复 HR，也不会自动跟进**；跟进必须人工批准；
- **不会自动启动任务**；每次真实投递都由你点击开始；
- **REVIEW / UNKNOWN / PENDING 不等于成功**，系统会停在需要人判断的地方；
- 任何身份、预算、发送结果不确定的情况，系统会 **fail-closed**，不会猜着发。

## 1. 开始前准备

### 1.1 必备

| 项目 | 说明 |
|---|---|
| Windows 电脑 | Windows 10/11 x64 |
| Google Chrome | 用于 BOSS 页面自动化；系统已安装即可 |
| BOSS 直聘账号 | 能正常扫码登录、能正常沟通 |
| AI 模型服务 | 任意 OpenAI 兼容接口：Base URL、模型名、API Key；没有它 AI 匹配和话术不会工作 |
| 桌面空间 | 首次运行约 450 MB（程序 + Java/Node 运行时） |

### 1.2 可选

- 一张图片简历：PNG / JPG / GIF / WebP，**不超过 10 MB**；
- 如果你想先小批量试跑，准备 **1 个关键词** 和 **1 个城市**。

### 1.3 不要做的事

- 不要把整个程序目录直接发给别人；使用后会包含 Cookie、API Key、岗位和联系人数据；
- 不要在没有确认模型和模板的情况下直接开始真实投递；
- 不要在 Chrome 已经登录多个 BOSS 账号时混用同一个浏览器 profile。

## 2. 第一次启动

### 2.1 找到程序

桌面上应有：

```text
OfferChaser-2.0.1\        ← 程序目录
OfferChaser 2.0.1.lnk     ← 快捷方式
```

也可以直接进入程序目录，双击：

```text
OfferChaser.vbs
```

它会后台启动并常驻托盘，适合日常使用。

如果想看日志，双击：

```text
启动.bat
```

会保留一个控制台窗口，启动和停止都更直观。

### 2.2 等待启动

首次启动约 **10–30 秒**。程序会：

- 启动本机后端；
- 初始化数据库；
- 启动管理台；
- 初始化 BOSS 浏览器环境；
- 自动打开管理台页面。

正常情况下会弹出浏览器窗口和管理台页面。管理台地址：

```text
http://127.0.0.1:6866
```

后端 API：

```text
http://127.0.0.1:9527
```

### 2.3 如果没自动打开

手动打开浏览器访问：

```text
http://127.0.0.1:6866
```

如果打不开：

1. 看桌面右下角托盘是否有 OfferChaser 图标；
2. 查看 `target\logs\launcher.out.log` 和 `target\logs\offerchaser.log`；
3. 双击 `停止OfferChaser.vbs`，再双击 `OfferChaser.vbs` 重试；
4. 确认 9527 / 6866 没有被其它程序占用。

---

## 3. 解锁管理台

管理台有本机会话认证，第一次会显示登录门。

### 3.1 找到本机令牌

打开程序目录：

```text
data\local-session-token
```

用记事本打开，复制其中的令牌。

> 这个令牌相当于本机管理台钥匙，不要发给别人。

### 3.2 登录

在登录门中：

1. 粘贴 `local-session-token` 的内容；
2. 可以点“显示/隐藏”确认内容；
3. 点击 **登录管理台**。

成功后进入管理台。

如果反复失败，先关闭页面，确认后端仍在运行，再重新打开；连续失败过多会短暂限流，等一分钟再试。

---

## 4. 登录 BOSS 直聘

首次启动时会打开一个 Chrome 窗口用于 BOSS。

### 4.1 扫码

1. 找到程序打开的 BOSS 页面；
2. 使用 BOSS App 扫码登录；
3. 保持 Chrome 窗口打开，不要手动关掉；
4. 登录态会保存在 `browser-data\` 中，后续启动通常不需要重新扫码。

### 4.2 确认登录

回到管理台，看顶栏运行胶囊/健康点和页面提示。

如果开始任务时提示“未登录”：

- 回到 Chrome 登录页重新扫码；
- 或关闭程序后重新启动，再看 BOSS 页面。

> 第一次启动时 `isLoggedIn=false` 是正常的，因为程序没有附带任何登录态。

---

## 5. 配置模型服务

进入顶部 **配置** 空间（`/boss/setup`）。

### 5.1 填写模型服务

找到 **模型服务（全局）** 卡片：

| 字段 | 怎么填 |
|---|---|
| API Base URL | 你的 OpenAI 兼容接口地址，例如服务商提供的地址 |
| 模型名称 | 服务商提供的模型 ID |
| API Key | 你的密钥 |

点击 **保存模型配置**。

说明：

- API Key 读取时只显示掩码 `********`；
- 原样保存掩码不会覆盖真实 Key；
- 这是全局配置，不随模板切换；
- 保存后下一次 AI 请求/下一轮任务生效。

### 5.2 测试是否配置正确

当前没有单独的模型测试按钮。最稳妥的方式：

1. 先配置一个关键词和模板；
2. 开始一轮小批量任务；
3. 在记录/评估中查看 AI 结果：
   - `MATCH` 说明模型和网络正常；
   - `ERROR` 或 AI 错误码说明地址/Key/模型名或网络有问题。

---

## 6. 创建方向模板

进入顶部 **配置** 空间的“方向模板”。

模板 = 一整套投递策略：搜索条件 + 筛选规则 + AI 提示词 + 图片简历 + 投递开关。

### 6.1 新建模板

1. 点击 **新建模板**；
2. 填名称，例如“产品方向”；
3. 可填方向和描述；
4. 点击创建。

新模板默认不激活。

### 6.2 编辑模板

选中模板，点击 **编辑配置**。

#### ① 搜索条件

建议先做小批量：

- 关键词：先只填 1 个；
- 城市：只选你真正想投的城市；
- 职位类型、行业、经验、学历、薪资、规模、融资：不确定就保持默认或“不限”；
- 采集策略：
  - 每关键词候选上限：建议先填 `1–2`；
  - 单关键词采集时长：建议 `2–5` 分钟；
  - 连续无新增窗口：默认 `10–30` 秒即可。

#### ② 筛选规则

第一次使用建议先保留默认规则。重点看：

- 最高学历；
- 薪资策略；
- 期望月薪；
- 公司/岗位/HR 黑白名单；
- HR 活跃过滤。

规则页支持预览；**预览不会发送、不会写评估**。

#### ③ AI 评估

- 打开 AI 启用开关；
- 检查 AI 介绍是否符合你的真实经历；
- 检查提示词是否要求严格 JSON / 不通过就拒绝；
- 不要把“AI 失败”改成“发送原文”。

#### ④ 简历与基本信息

- 可上传一张图片简历；
- 图片 ≤10 MB；
- 不上传也能先投文字，但图片简历功能不会生效；
- 模板名称也可在这里修改。

### 6.3 保存并激活

1. 底部出现“有 N 处未保存改动”后，点击 **保存配置**；
2. 保存成功后回到模板列表；
3. 点击 **激活**；
4. 确认“下一轮任务生效”。

注意：

- 激活不会立即发送任何消息；
- 下一轮任务开始前会按模板校正当前配置；
- 非生效模板只保存快照，不会影响当前任务。

---

## 7. 第一次小批量试跑

第一次一定不要直接放开大范围投递。

### 7.1 建议参数

| 参数 | 建议 |
|---|---|
| 关键词 | 1 个 |
| 每关键词候选上限 | 1–2 |
| 单关键词采集时长 | 2–5 分钟 |
| 每日首次沟通预算 | 默认即可 |
| AI | 开启 |
| 图片简历 | 有就开，没有就关 |

### 7.2 开始

1. 回到顶部 **今日** 空间；
2. 查看顶栏运行胶囊，确认空闲；
3. 点击 **开始投递**；
4. 观察运行胶囊、管线、事件流；
5. 不建议离开电脑太久，第一次先盯着走完。

### 7.3 运行中

可能看到：

- 采集中；
- 规则筛选；
- 进入 AI 匹配；
- 预算/身份核对；
- 文字/图片发送确认；
- 完成或停止。

如果发现异常，点击运行胶囊的 **停止投递**，确认停止；不要直接杀进程，系统会先尝试让 worker 退出。

## 8. 看结果与处理需要人工判断的事

一轮结束后，结果会出现在：

### 8.1 今日

- 运行状态；
- 今日文字确认数；
- 待人工核对数；
- 预算使用情况；
- 阶段管线；
- 今日状态同步。

### 8.2 待办（`/boss/inbox`）

待办分 4 类：

| 类型 | 含义 | 怎么处理 |
|---|---|---|
| 待核对 | 发出结果 UNKNOWN，不能确认成功 | 选裁定结果 + 填原因 → 提交人工核对 |
| 待放行 | 规则/AI REVIEW 的人工放行队列 | 批准入队或拒绝；批准后下一轮才执行 |
| 建议跟进 | 跟进计划待批准 | 批准或拒绝；批准只允许下一轮执行 |
| 图片补发 | 文字已确认但图片失败/未知 | 生成补发计划，仍需人工批准 |

所有决策都要求：

- 填写原因（必填，≤500 字）；
- 二次确认；
- 409 冲突时刷新数据，不自动重试。

### 8.3 记录（`/boss/ledger`）

- 投递明细：文字/图片状态、事件证据、人工核对入口；
- 评估记录：规则/AI 原因，可“用当前规则重评”；
- 任务记录：本轮模板、停止原因、错误；
- 联系人：回复状态、人工接管/停止联系。

### 8.4 洞察（`/boss/insights`）

- 日期范围；
- 趋势指标；
- 采集来源；
- 跟进策略说明。

### 8.5 状态同步

在今日空间点击 **读取今日投递状态**：

- 只读 BOSS 聊天；
- 统计已投递/已读/已回复/未读/未知；
- 会自动把读到的 HR 回复回写联系人；
- 不会发送消息。

---

## 9. 停止与退出

### 9.1 只停止任务

在运行胶囊中点击 **停止投递**，确认；等待状态变为停止/完成。

### 9.2 完全退出

- 托盘图标右键 → 退出；
- 或双击 `停止OfferChaser.vbs`；
- 或关闭 `启动.bat` 的控制台窗口（仅对通过该窗口启动的服务）。

停止时会：

1. 先请求后端停止任务；
2. 等 worker 退出；
3. 超时才兜底结束进程。

## 10. 数据、备份与升级

### 10.1 数据在哪

```text
db\offerchaser.db      SQLite 数据库
data\                  本机会话令牌、运行数据
browser-data\          BOSS 登录态
target\logs\           日志
```

这些目录含个人敏感数据，**不要直接打包发给别人**。

### 10.2 自动备份

程序会在任务启动前/数据库升级前自动备份到 `db\backups\`。需要手动备份时，退出程序后复制：

```text
db\
data\
browser-data\
```

### 10.3 升级程序

1. 先停止任务并退出；
2. 备份上面的数据目录；
3. 用新包的 `OfferChaser.jar`、`src\main\resources\dist`、运行时文件替换旧包；
4. 不要覆盖 `db\`、`data\`、`browser-data\`；
5. 重新启动。

## 11. 常见问题

| 现象 | 处理 |
|---|---|
| 管理台打不开 | 检查托盘/端口 9527、6866；重启程序；看 `target\logs\offerchaser.log` |
| 登录门一直失败 | 检查 `data\local-session-token`；等待一分钟后再试，避免限流 |
| 开始按钮不可用 | 看是否运行中/停止中/worker 未退出；用停止或强制复位 |
| 提示 BOSS 未登录 | 在 BOSS Chrome 窗口重新扫码；不要关闭窗口 |
| AI 全部 ERROR | 检查模型服务 Base URL、模型名、API Key、网络 |
| 邮箱/HR 回复了但系统仍准备联系 | 先执行“读取今日投递状态”，查看联系人是否 REPLIED；若已回复系统会在发送前复检阻断 |
| 任务卡住 | 先停止，再强制复位；看日志；不要直接杀进程 |
| 409 冲突 | 刷新页面，按最新状态重新操作 |
| 图片补发没有自动执行 | 设计如此；生成计划后到待办批准，下一轮才执行 |
| 数据误删 | 从 `db\backups\` 选择最近备份，退出程序后替换 `db\offerchaser.db` |

## 13. 一句话版本

**启动程序 → 解锁管理台 → 扫码登录 BOSS → 配置模型服务 → 创建并激活一个只投 1 个关键词的小模板 → 今日点开始 → 等待完成 → 在待办处理需要人工判断的事项 → 查看记录与状态同步 → 停止/备份。**

第一次不要放量，先跑通一轮，再逐步增加关键词、采集上限和每日预算。

# OfferChaser 管理台 · UI 设计系统摘要（V3）

> 当前实现：5 个空间 + 顶栏运行胶囊 + 三套配色。完整视觉规格与落地说明见 [10-ui-redesign-v3](10-ui-redesign-v3.md)。本页只保留设计系统速查。

## 1. 信息架构

| 空间 | 路由 | 回答的问题 |
|---|---|---|
| 今日 | `/boss` | 现在跑得怎么样、有什么要处理 |
| 待办 | `/boss/inbox` | 哪些事项需要拍板 |
| 记录 | `/boss/ledger` | 之前发生了什么 |
| 配置 | `/boss/setup` | 怎么改投递策略 |
| 洞察 | `/boss/insights` | 效果如何 |

旧路由全部保留客户端重定向，书签不失效。顶栏 `TopBar` 是唯一全局壳：空间滑块、运行胶囊、旧入口跳转、通知条、主题、锁定。

## 2. 全局元素

- **运行胶囊**：全站唯一起始/停止/继续/强制复位入口，复用 `use-boss-status`，停止和强制复位有二次确认；
- **通知条**：仅在等待人工验证 / 失败 / 已完成时出现，展示状态、停止原因、错误；
- **跳转面板**：`Ctrl/⌘+K`，覆盖 5 个空间与旧入口；
- **主题**：`graphite` 石墨铜、`porcelain` 瓷白靛、`ivory` 象牙松，保存在 localStorage；
- **登录门**：本机会话 Cookie + CSRF；锁定触发登录门；
- **健康点/待办徽章**：健康状态与全部待处理数。

## 3. 状态颜色

| 语义 | Token | 使用 |
|---|---|---|
| 强调 / 进行中 / 待操作 | `--v3-accent` | 主按钮、当前空间、进行处理 |
| 已确认 | `--v3-ok` | 仅限后端确认的送达结果 |
| UNKNOWN / REVIEW / PENDING | `--v3-warn` | 待核对、待放行、待批准 |
| 失败 / 危险 | `--v3-bad` | 失败状态、强制复位、删除 |
| 中性 | `--muted` | 已拒绝、无状态、弱信息 |

“已批准/已入队”使用强调色浅底，不使用成功绿，避免被误读为已发送。

## 4. 字体与布局

- Inter（西文/数字，tabular-nums）+ 系统中文字体；ID、runId、时间用 JetBrains Mono；
- 页面标题 30、卡片标题 15、正文 14、辅助 12–13、大数字 38–46；
- 圆角：大卡 20、中卡 14–16、按钮/输入 10–12、胶囊 999；
- 页面左右 32、卡片内边距 22–28、区块间距 20；
- 版心最大 1360、居中；窄屏 flex-wrap，表格横向滚动；触控目标 ≥40。

## 5. 动效

空间滑块 420ms；内容上浮 600ms；详情切换 380ms；数字/预算环/管线生长 1000ms；运行点呼吸 1.9s；弹窗 300ms；确认条 350ms；折线重绘 1000ms。

全部动效在 `prefers-reduced-motion: reduce` 下关闭，数字直接显示终值。

## 6. 关键交互原则

- 任何发送相关动作都不提供“快捷键放行”；
- 人工放行、跟进批准只入队，下一轮执行；
- UNKNOWN/REVIEW/PENDING 绝不显示成功色；
- 409 版本冲突必须展示并刷新，不自动重试；
- 写入失败保留已有数据，不切换成空态；
- 表格/列表保留状态、原因、版本、时间、证据、禁用原因。

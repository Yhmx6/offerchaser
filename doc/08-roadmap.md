# 08 · 路线图与已知限制

本文件只写**可验证的下一步**与明确边界，不写日期承诺、不承诺未实现能力。
任何“计划中”能力在当前版本都不可用；以代码和 [05-testing](05-testing.md) 的基线为准。

## 1. 已知限制（当前版本）

| 类别 | 限制 | 影响/边界 |
|---|---|---|
| 平台 | 只支持 BOSS 直聘 | 平台切换不启用；平台门会拒绝非 BOSS API |
| 账号 | 本机单用户、单 BOSS 账号 | 无多用户/多账号/远程访问 |
| 自动化 | 真实投递只能手动开始 | 无定时启动、无无人值守调度 |
| 跟进 | 不自动回复 HR、不自动跟进 | 跟进计划必须人工批准，只允许下一轮执行 |
| 图片补发 | 只生成图片补发计划 | 不自动执行；仍需人工/后续能力 |
| 模板 | 无模板版本留存/回滚 | 覆盖后不能一键回退；可复制模板做近似备份 |
| 模板排序 | 桌面 HTML5 拖拽 | 移动端触摸拖拽未实现 |
| 状态同步 | 依赖 BOSS 聊天页可读性 | 打开会话可能被平台标记已读；未匹配到聊天的投递记 DB_ONLY/UNKNOWN |
| 状态同步 | 统计口径按“本次读取可见聊天” | 聊天被删除/未加载/翻页限制会低估；不保证实时 |
| 识别 | BOSS DOM 可能变化 | 选择器失效会导致发送/核对 fail-closed 停住，而不是误发 |
| AI | 依赖外部模型服务 | 超时 45s；异常/不合法输出不发送；模型质量影响通过率 |
| 数据 | SQLite 单机文件 | 无内置跨机同步/高可用；备份需本机操作 |
| 页面 | 静态导出 | 无服务端渲染/动态路由；详情用抽屉/query |
| 移动端 | 管理台按桌面设计 | 小屏可用但非主要目标；表格可能横向滚动 |

## 2. 优先级原则

1. **安全与正确性优先**：任何会误发、错记、丢数据的缺陷优先于功能。
2. **可观测性优先**：先能定位失败，再谈优化。
3. **人工闭环优先于全自动**：在平台规则/风控不明时，人工批准/放行是产品特性而非过渡方案。
4. **不引入不可控依赖**：保持本地单用户、静态管理台、本机数据库。

## 3. 下一步候选（按优先级）

### P0 · 稳定性与安全

| 项 | 要解决的问题 | 验收标准（可测） |
|---|---|---|
| BOSS DOM 自检与告警 | 页面结构变化后尽早发现，而不是任务中静默失败 | 启动/任务预检输出关键选择器自检结果；失败给出明确日志与面板提示 |
| 状态同步健壮性 | 聊天列表分页/删除/未加载导致统计偏差 | 明确“本次可见/上限 40 会话”口径并在页面展示；异常记录 FAILED 可重试 |
| 发送链路端到端审计 | 复核“不发送/UNKNOWN”判定是否符合预期 | 每次拦截均写 `delivery_event` + 可在明细详情查看原因 |
| 备份恢复演练 | 迁移/恢复流程只在副本验证过 | 文档化演练步骤 + 一键校验备份可打开/完整性 |
| 依赖与版本巡检 | Spring Boot/Playwright/Chrome 升级风险 | 升级前跑全量 + 浏览器/UI 门禁，记录兼容结论 |

### P1 · 使用价值

| 项 | 要解决的问题 | 验收标准 |
|---|---|---|
| 模板版本留存/回滚 | 覆盖模板后无法回退 | 模板快照版本化；支持查看/回滚到先前快照版本（含内容校验） |
| 跟进闭环增强 | 目前只到“人工批准 + 下一轮执行” | 跟进效果标记、失效原因可视化；仍默认不自动发送 |
| 图片补发自动执行（可选） | 补发计划目前只生成 | 仅在人工批准 + 身份/预算/确认全通过时执行；默认关闭 |
| 人工放行体验 | REVIEW 岗位处理效率 | 批量批准/拒绝（带理由与审计）、失败原因聚合、重试入口 |
| 指标口径完善 | 看板与状态同步口径需一致 | 指标 definitions 与状态同步/台账一致，有对照测试 |
| 采集策略可视化 | 模板采集策略生效情况不直观 | 模板详情展示当前策略与全局默认的差异/生效轮次 |

### P2 · 体验与扩展

| 项 | 说明 |
|---|---|
| 移动/触摸拖拽排序 | 模板排序在触屏设备可用；桌面保持现交互 |
| 页面密度全局化 | 目前仅明细页可切密度；可评估扩展但需避免破坏信息层级 |
| 主题/品牌定制 | 设计令牌已集中，可在不破坏语义色的前提下调整 |
| 单机多账号（谨慎） | 会改变预算/联系人/身份模型，需独立设计与安全评审，不建议短期做 |

## 4. 明确不做（非目标）

- 不自动回复 HR、不自动发起/执行跟进（需要人工批准）。
- 不做云端多租户/远程管理/公网暴露。
- 不做无人值守定时投递（真实发送必须手动启动）。
- 不绕过平台风控/验证；验证时暂停并等待人工。
- 不提供“保证投递成功/保证回复”的承诺。
- 不恢复平台切换页面与非 BOSS API。

## 5. 路线图使用方式

- 新需求先判断属于 P0/P1/P2 还是非目标；P0 安全/正确性优先。
- 每个候选项实现前补“验收标准”，实现后补测试与文档，更新 [05-testing](05-testing.md) 基线。
- 不把“计划中”写进 README/项目说明的能力列表，避免用户误解当前可用范围。
